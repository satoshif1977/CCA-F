Q001Solution Architecture Design
🇯🇵 Japanese
大規模エンタープライズが厳格な SLA 要件のもと 10,000 同時ユーザー向けに Claude を導入する。本番信頼性を最も高めるアーキテクチャパターンは何か？
✓ 正解
セマンティックキャッシュで類似プロンプトの再利用・指数バックオフ付きレート制限・サーキットブレーカーによる API 障害の遮断、の三層を組み合わせる。
💡 暗記ポイント
高同時接続・SLA 系で必ず問われる三点セット。① セマンティックキャッシュ：類似プロンプトへの重複 API 呼び出しをキャッシュで吸収しコスト・レイテンシを削減。② 指数バックオフ：レート制限時に待機時間を指数的に増やしてカスケード障害を防止。③ サーキットブレーカー：連続失敗時に API 呼び出しを一時遮断して全体を保護。これら三層がないと 1 点の障害が全体に波及する。
🇺🇸 English
A large enterprise must deploy Claude for 10,000 concurrent users under strict SLA requirements. What architectural pattern MOST ensures production reliability?
✓ Correct Answer
Implement three layers: semantic caching to absorb repeated prompts, rate limiting with exponential backoff to prevent cascading failures, and circuit breakers to isolate API outages.
🔑 Key Words
semantic cachingセマンティックキャッシュ類似プロンプトを再利用して重複 API 呼び出しを削減するキャッシュ戦略
exponential backoff指数バックオフレート制限時に待機時間を指数的に増やして再試行するパターン
circuit breakerサーキットブレーカー連続障害時に API 呼び出しを一時遮断してシステム全体を保護するパターン
cascading failureカスケード障害1 点の障害が連鎖して全体に波及する障害パターン

Use Claude through Amazon Bedrock with cross-region inference profiles, which automatically distribute traffic across compliant regions with built-in failover.

Q003Solution Architecture Design
🇯🇵 Japanese
RAG システムに最高性能モデルを使っているのに回答精度が低い。最初に調査すべき原因は何か？
✓ 正解
取得コンテキストチャンクの関連性と品質。RAG では検索品質が回答精度の主要決定因であり、最高性能モデルでも無関係・低品質なコンテキストからは正確な回答を生成できない。
💡 暗記ポイント
RAG の黄金律：「ゴミを入れればゴミが出る（Garbage In, Garbage Out）」。モデルが強力でも検索が悪ければ精度は上がらない。調査順序は ① 検索クエリと取得チャンクの関連性スコア → ② チャンクの分割サイズ・オーバーラップ設定 → ③ エンベディングモデルの選択 → ④ リランキング（再順序付け）の有無。モデルのアップグレードは検索品質改善より後回しにする。
🇺🇸 English
A RAG system using the most capable model still returns inaccurate answers. What should be investigated first?
✓ Correct Answer
The relevance and quality of retrieved context chunks. In RAG systems, retrieval quality is the primary determinant of accuracy—even the best model cannot generate correct answers from irrelevant context.
🔑 Key Words
RAG (Retrieval-Augmented Generation)検索拡張生成外部ナレッジを検索してモデルへ渡し精度を向上させる手法
context chunk qualityコンテキストチャンク品質取得した文書断片の関連性・正確性・適切な分割サイズ
retrieval quality検索品質ユーザークエリに対する取得結果の関連性の高さ
rerankingリランキング（再順序付け）取得した複数のチャンクを関連性スコアで再並び替えする手法

Implement intelligent routing: classify document complexity and route complex contracts to Claude Opus while processing standard documents with Claude Sonnet.

Q005Model Selection & Prompting
🇯🇵 Japanese
本番パイプラインで Claude に特定のスキーマに準拠した JSON を常に出力させたい。最も信頼性の高いプロンプトエンジニアリング手法は？
✓ 正解
スキーマ仕様を含むシステムプロンプトと、正しい JSON 出力の few-shot 例を組み合わせる。説明より実例（デモンストレーション）がフォーマット遵守に最も効果的。
💡 暗記ポイント
フォーマット遵守の鉄則：① システムプロンプトに JSON スキーマ（フィールド名・型・必須か否か）を明記 → ② few-shot 例で「このように出力してください」と実例を見せる → ③ 必要なら事前充填（prefilling）でアシスタントターンを `{` から始める。temperature の調整や max_tokens の増減はフォーマット遵守に無効。
🇺🇸 English
A production pipeline requires Claude to always output valid JSON matching a specific schema. What prompt engineering technique is MOST reliable?
✓ Correct Answer
Combine a system prompt with the exact JSON schema specification and few-shot examples demonstrating correct output. Showing examples is more reliable than describing the format.
🔑 Key Words
few-shot examplesfew-shot 例望ましい出力の実例を複数示して出力形式を誘導する技術
system prompt schemaシステムプロンプトスキーマ出力の構造・型・必須フィールドをシステムプロンプトに明記する手法
prefilling事前充填（プレフィリング）アシスタントターンを途中から始めて出力形式を強制する技術
format adherenceフォーマット遵守指定した出力形式に一貫して従わせること

🇯🇵 Japanese
1 日数千件の問い合わせを処理するカスタマーサービスボットに一貫性と予測可能な応答が求められる。最適なモデルと設定の組み合わせは？
✓ 正解
Claude Sonnet + temperature=0 + 丁寧に設計されたシステムプロンプト。Sonnet は高頻度ワークロードで性能とコストのバランスが最良、temperature=0 は決定論的な出力を保証する。

カスタマーサービスの設定テンプレート：モデル = Sonnet（Opus はコスト過多・Haiku は複雑クエリが苦手）、temperature = 0（一貫性が最優先）、システムプロンプト = ペルソナ・禁止事項・応答形式を定義。temperature > 0 にすると同じ質問に毎回違う答えが返り品質管理が困難になる。
🇺🇸 English
A customer service bot handling thousands of daily queries requires consistent, predictable responses. What is the optimal model and configuration combination?
✓ Correct Answer
Claude Sonnet with temperature=0 and a carefully crafted system prompt. Sonnet offers the best capability-cost balance for high-volume service; temperature=0 ensures deterministic output.
🔑 Key Words
temperature=0temperature ゼロ同じ入力に常に同じ出力を返す決定論的モード

Q007Integration & Implementation
🇯🇵 Japanese
エンタープライズが MCP（モデルコンテキストプロトコル）を通じて Claude に社内データベースへのアクセスを付与する。MCP サーバー層で最も重要なセキュリティ設計判断は何か？
✓ 正解
最小権限アクセス制御による認証・認可を MCP サーバー層に実装する。各ツールは必要最低限のデータにのみアクセスでき、すべてのリクエストは認証済みであることを保証する。
💡 暗記ポイント
MCP セキュリティの核心：MCP サーバーは Claude とバックエンドの間のゲートキーパー。① 認証（Authentication）：リクエストが正規のシステムから来ているか検証。② 認可（Authorization）：そのツールが要求データにアクセスする権限があるか確認。③ 最小権限（Least Privilege）：ツールごとに必要最小限の権限のみ付与。暗号化やログは補完的制御であり、認証・認可が主要防衛線。
🇺🇸 English
An enterprise MCP server gives Claude access to internal databases. What is the most critical security design decision at the MCP server layer?
✓ Correct Answer
Implement authentication and authorization with least-privilege access controls at the MCP server layer, ensuring each tool accesses only the minimum data required and all requests are verified.
🔑 Key Words
MCP (Model Context Protocol)モデルコンテキストプロトコルClaude などの AI モデルに外部ツール・データへのアクセスを提供するプロトコル
least-privilege最小権限必要最低限の権限のみを付与するセキュリティ原則
authentication / authorization認証 / 認可本人確認（認証）とアクセス許可判断（認可）の二段階セキュリティ
tool-level access controlツールレベルアクセス制御MCP の各ツールごとに個別にアクセス権を設定する細粒度の制御
Q008Integration & Implementation
🇯🇵 Japanese
エージェントワークフロー中に Claude がツールを呼び出し HTTP 503 エラーを受け取った。システムは Claude に何を返すべきか？
✓ 正解
エラー種別・コンテキスト・推奨される次のアクションを含む構造化エラーメッセージを返す。これにより Claude は再試行・代替ツール・ユーザーへのエスカレーションを自律的に判断できる。
💡 暗記ポイント
エラーハンドリングの設計原則：「Claude に判断の材料を渡す」。❌ 汎用エラーをそのまま渡す → Claude は何をすべきか不明。❌ ワークフローを即終了 → 全進捗を失う。✅ 構造化エラー（エラーコード + 状況 + 提案アクション）→ Claude が適切な次手を選択できる。HTTP 503 は一時的な過負荷なので「しばらく待って再試行」を suggested action に含めるのが理想。
🇺🇸 English
Claude calls a tool during an agentic workflow and receives an HTTP 503 error. What should the system return to Claude?
✓ Correct Answer
Return a structured error message containing the error type, context, and suggested next actions—enabling Claude to autonomously decide whether to retry, switch to an alternative approach, or escalate.
🔑 Key Words
structured error message構造化エラーメッセージAI が次のアクションを判断できる情報を含む機械可読なエラー形式
agentic loopエージェントループツール呼び出しと判断を繰り返して自律的にタスクを進める処理サイクル
graceful degradationグレースフルな劣化一部失敗してもシステム全体が継続できるよう設計する考え方

ストリーミング応答を使うカスタマーサポート統合がモバイル回線でサイレントに失敗することが多い。どのような実装が必要か？
✓ 正解
タイムアウト検知・自動再接続ロジック・グレースフルな劣化の三点を実装する。ストリームが中断された場合は全応答を失うのではなく、受信済みの部分的な応答をユーザーに届ける。
💡 暗記ポイント
本番ストリーミングの必須実装：① タイムアウト検知：一定時間 token が来なければタイムアウトと判定。② 再接続：一時的なネットワーク切断後にストリームを復旧。③ グレースフル劣化：完全な失敗ではなく部分的な応答を表示。モバイル回線はサイレント切断（接続を持ったまま応答が来ない状態）が多く、タイムアウト設計なしでは無限待機になる。
🇺🇸 English
A streaming-based customer support integration frequently fails silently on mobile networks. What implementation is required?
✓ Correct Answer
Implement timeout detection, automatic reconnection logic, and graceful degradation—deliver partial responses received so far if a stream is interrupted rather than losing the entire response.
🔑 Key Words
streamingストリーミング生成されたトークンをリアルタイムに順次クライアントへ送信する方式
silent failureサイレント障害エラーを返さずに接続が停止する検知困難な障害パターン
timeout detectionタイムアウト検知一定時間応答がない場合に処理中断を判定する仕組み

✓ 正解
定義されたルーブリックを持つ LLM-as-judge を大規模に適用し、人間のアノテーションで較正する。自動評価のスケールと人間の品質基準の両立が実現できる。
💡 暗記ポイント
評価の規模別最適手法：小規模（〜100件）= 人間評価のみ。中規模（〜1万件）= 人間評価+サンプリング。大規模（1万件超）= LLM-as-judge。ただし LLM-as-judge は人間較正なしだとジャッジモデルのバイアスを評価してしまう。必ず人間アノテーション（200-500 件）でジャッジモデルと人間の判断の相関を確認してから大規模適用する。自己評価（Claude が自分を評価）は過大評価バイアスがあるため不可。
🇺🇸 English
A team needs to evaluate Claude's performance across 50,000 daily customer service interactions. Manual review does not scale. What evaluation approach is MOST appropriate?
✓ Correct Answer
Apply LLM-as-judge with defined rubrics at scale, calibrated against human annotations to ensure alignment with actual quality standards.
🔑 Key Words
LLM-as-judgeLLM-as-judge（LLM 審判）別の LLM を審判として使いモデル出力を自動評価する手法
rubricルーブリック（評価基準）評価軸と採点基準を明文化したスコアリング指針

本番の Claude デプロイメントで 3 ヶ月かけて品質が徐々に低下しているが根本原因が不明。体系的に原因を特定する評価手法は？
✓ 正解
ゴールデン例を含む回帰テストスイートを確立し、現在の出力とベースラインを体系的に比較する。これによりプロンプト変更・データ分布シフト・API 更新のどれが原因かを分離できる。

性能劣化の診断フレームワーク：① ゴールデン例（回答が既知の正解セット）を 100-500 件用意。② 劣化前後の出力をゴールデン例で採点し差分を測定。③ 変数を 1 つずつ分離：プロンプトを固定→データ分布確認→API バージョン確認。「なんとなくプロンプトを書き直す」は推測診断であり、回帰テストによる体系的な比較が唯一の信頼できる診断法。

A Claude deployment's quality has gradually degraded over 3 months and the root cause is unclear. What methodology systematically identifies the cause?
✓ Correct Answer
Establish a regression test suite with golden examples, then systematically compare current outputs against the baseline to isolate whether degradation stems from prompt drift, data distribution shifts, or API changes.
🔑 Key Words
regression test suite回帰テストスイート過去の既知の正解（ゴールデン例）と現在の出力を比較する自動テスト群
golden examplesゴールデン例品質ベースラインとして使用する期待出力の正解サンプル

Q013Evaluation & Testing
🇯🇵 Japanese
レッドチームテストで、精巧な入力によって Claude がシステムプロンプトの内容を漏洩させられることが判明した。最も効果的な多層防御戦略は何か？
✓ 正解
