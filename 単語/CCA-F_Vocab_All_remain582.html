❌ 誤答シグナル語
  • 🔴 over-engineered ─ 過剰な作り込み（MLルーティング層・投機的キャッシュ・別モデルへの切り替え）
  • 🔴 probabilistic ─ プロンプト任せの確率的対策。金銭・順序・コンプライアンスが絡む問題では誤答
  • 🔴 heuristic ─ ヒューリスティックで選択 → 複数一致で誤答側になりがち
  • 🔴 suppress ─ エラーを握りつぶす（失敗を成功として返す）
  • 🔴 speculative ─ 投機的キャッシュ等、根拠のない先読み対策
  • 🔴 shifts burden ─ 負担を開発者・人間に転嫁
  • 🔴 consensus ─ 多数決レビュー（断続的にしか現れない問題では機能しない）
  • 🔴 存在しない機能 ─ CLAUDE_HEADLESS変数 / --batchフラグ / .claude/config.json の commands配列
✅ 正解シグナル語
  • 🟢 directly addresses the root cause ─ 症状でなく根本原因への直接対処
  • 🟢 deterministic ─ programmatic enforcement による決定論的保証（プロンプト任せより強い）
  • 🟢 proportionate / low-effort, high-leverage ─ 釣り合いの取れた最小の一手
  • 🟢 structured ... ─ structured error context / structured handoff →「構造化された」は正解率高
  • 🟢 scoped / least privilege ─ 必要最小限のツール・権限のみ付与
  • 🟢 actionable ─ 対処可能なフィードバック
  • 🟢 使い分け・両取り ─ "matching each API to its appropriate use case"（要件ごとに適材適所）
  • 🟢 二重制約への対応 ─ "reduce A while maintaining B" → 両方の制約に触れている選択肢のみ正解
