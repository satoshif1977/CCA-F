Q1Agent architecture and orchestration
🇯🇵 Japanese
3つの異なるソース（交通量CSV・気象記事・規制文書）を統合するスマートシティエージェントが、単一の散文ブロックで出力するため構造と規制要件が失われている。このマルチモーダル情報を適切に表示するための最適なアーキテクチャは？
✓ 正解
コーディネーターエージェントが各ソースのコンテンツタイプ（'traffic_table', 'weather_report', 'regulations'）を特定するシステムを開発する。その後、この構造化されたデータと、「交通データはMarkdownテーブルとして表示する」「規制要件は番号付きリストとして要約する」といった明示的なレンダリング指示を統合エージェントに渡す。
💡 暗記ポイント
複数の異なる性質のデータを1プロンプトで処理すると「出力の均質化」が起きる。オーケストレーションパターンを採用し、コーディネーターが各データ種別に応じたレンダリング指示（Markdownテーブル・箇条書き等）を後続エージェントに渡す設計が最適。
🇺🇸 English
A smart city integration agent combines data from three sources — a traffic volume CSV, weather news articles, and regulatory documents. However, it outputs all results as a single unstructured prose block, causing table formatting and regulatory requirement numbering to be lost entirely. What is the optimal multi-agent architecture to correctly render this multimodal information in its appropriate format?
✓ Correct Answer
Develop a system where the coordinator agent identifies the content type of each source ('traffic_table', 'weather_report', 'regulations'), then passes this structured data along with explicit rendering instructions — such as 'display traffic data as a Markdown table' and 'summarize regulatory requirements as a numbered list' — to the integration agent.
🔑 Key Words

Q4Context management and reliability
🇯🇵 Japanese
Claude APIを使う予約システムで2種のエラーが発生：便番号の形式不正（400 Bad Request）とサーバー過負荷（503 Service Unavailable）。これら2つを適切に処理するロジックの正しい構成は？
✓ 正解
両方のエラーで isError: true を返す。400エラーには errorCategory: "validation"、isRetryable: false を設定し、ユーザーに正しい形式での入力を促す。503エラーには errorCategory: "transient"、isRetryable: true を設定し、再試行を提案する。
💡 暗記ポイント
400系（クライアントエラー）はリトライ無意味→ユーザーに入力修正を求める。503系（一時的サーバーエラー）は指数バックオフでリトライ有効。エラー原因（入力不備 vs 一時障害）で処理を分岐するのがベストプラクティス。
🇺🇸 English
A flight reservation system using the Claude API encounters two distinct error types: a 400 Bad Request when a flight number format is invalid, and a 503 Service Unavailable when the server is overloaded. What is the correct error-handling logic to appropriately distinguish and process both error types?
✓ Correct Answer
Return isError: true for both errors. For the 400 error, set errorCategory: 'validation' and isRetryable: false, prompting the user to correct their input. For the 503 error, set errorCategory: 'transient' and isRetryable: true, suggesting a retry after a brief wait.
🔑 Key Words
validation errorバリデーションエラー入力値が規則に合わない場合のエラー（400系）。再試行しても無意味
transient error一時的エラーサーバー過負荷など一時的な障害（500系）。待機後のリトライで解決可能
retryable再試行可能な同じリクエストを再送することで成功が見込めるエラーかを示すフラグ
error handlingエラーハンドリングエラーの種類に応じて適切な処理を行う設計
exponential backoff※ 関連概念指数バックオフリトライ間隔を 1秒→2秒→4秒… と指数的に延ばし過負荷を防ぐ戦略
Q5Claude Code configuration and workflows
🇯🇵 Japanese
Claude Codeで設計書を自動生成後、同じセッション内で要件との整合性を検証するステップを追加した。しかし明らかな不整合が見逃されることに気づいた。なぜこの現象が起き、どうワークフローを再構成すべきか？
✓ 正解

💡 暗記ポイント

🇺🇸 English
A Claude Code workflow automatically generates a design document and then adds a consistency-verification step within the same session to check alignment with requirements. Despite this, obvious inconsistencies are consistently overlooked. Why does this phenomenon occur, and how should the workflow be restructured to resolve it?
✓ Correct Answer
The model experiences confirmation bias due to retaining its own recent generation context — it is biased toward validating its just-produced output and is therefore unlikely to identify flaws within the same session. A completely independent new Claude Code session should be started for the verification step.
