★ 設問ごとの配点は公開されていません。「後半の設問ほど配点が高い」という説は広く言われますが、公式の裏付けはありません。ただし結論（最後まで解く）は変わりません。

経験則 問題の選び方

  • 最初の10行ほどで分野と難易度を見極め、早めに選択を決める。迷う時間が最大の損失
  • 構成図・権限表・ログが出ている問題は、インフラ実務の経験がそのまま効く
  • 逆に HTML / ECMAScript のソースが大量に出ている問題は、読み慣れていないなら避ける判断もある
  • ただし Web 系は 20問中8問。全部避けると選択肢が足りなくなります
★ 外部情報を読むときの注意

ネット上の「午後I 対策」「午後II 対策」の記事は、令和5年秋より前の旧形式（午後I 90分＋午後II 120分）を前提にしています。現行は 150分で4問中2問。時間配分の数字をそのまま使わないでください。

公式＋経験則 書き方

公式の備考欄左の例に限らず、本文の状況に沿った仕組み、手順が記述されていること
  • 白紙にしない。部分点が実際に設計されています
  • 分からなければ 本文の該当箇所をそのまま写す。一般論を書くより点になりやすい
  • 設問の語尾に線を引く ─「〜から」「〜ため」なら理由、「どのように」なら手順、「何を」なら対象
  • 「する／しない」「許可／拒否」に印を付ける ─ 反対を答えるケアレスミスが公式に名指しされています

AIの利用をめぐるサイバーリスク（3位・初登場）

2026年版で初めて選出された脅威です。令和8年度はこの版が最新なので、出る可能性があります。従来の教材には載っていません。

3つに分けて覚える

① 情報漏えい
社員が外部の生成AIサービスに機密情報を入力してしまう。入力内容が学習や保存に回る。
② AIシステムへの攻撃
プロンプトインジェクション。特に間接型は、AIが読み込む外部データ（Webページ・文書）に指示を仕込み、AIに実行させる。
③ ディープフェイク
経営者や取引先の声・映像を偽造して不正送金させる。BEC の高度化版。
対策の第一歩は「社内AI利用ルールの整備」（IPA）。技術的対策と組み合わせることが重要、とされています。
記述で書くなら ─ 入力してよい情報の範囲を定めた利用ルールを整備し、周知する。
★ 実務にも直結します

間接プロンプトインジェクションは、RAG や エージェントに外部データを読ませる構成で現実の問題になります。「取り込んだ文書に指示文が埋まっていたら、AI がそれを命令として実行してしまう」という構図です。信頼できないデータを命令として扱わせない設計（入力の分離・出力の検証・権限の最小化）が答えになります。

JVN / CVE / CVSS / EPSS の関係

R7春は問2と問4の2問がここでした。4つの役割分担さえ言えれば戦えます。

名前正式名称役割
CVECommon Vulnerabilities and Exposures脆弱性に付ける通し番号。「どの脆弱性か」を一意に指す
CVSSCommon Vulnerability Scoring System深刻度を 0〜10 で表す。最新は v4.0（R7春問4 で出題）
EPSSExploit Prediction Scoring System悪用される確率。FIRST が公開
JVNJapan Vulnerability NotesJPCERT/CC と IPA が運営する情報ポータル
KEVKnown Exploited Vulnerabilities米CISA が公開する実際に悪用が確認された脆弱性の一覧

★ 優先度は「深刻度だけ」では決めない

公式解答例（R7春問2）（現状値は）攻撃コードなどの情報を多くの公開サイトにある情報から判断する必要があるから
（EPSS値は）FIRST のサイトで公開されている値をそのまま使えばよいから
公式解答例（R7春問2）診断時に実際に悪用できることを確認しているから

答えの骨格：CVSS（深刻度）＋ EPSS/KEV（悪用の現実性）＋ 自社環境での影響 の3つで決める。
